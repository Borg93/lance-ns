Before you start

Open the cluster

The stack is deployed with the plain make flow (not Tilt — Tilt is only for hot-reload dev). It's already live; you just need eyes on it.

# the tools live in ./.localbin — put them on PATH once per shell
export PATH="$PWD/.localbin:$PATH"

# open k9s — the whole demo is watched here
make k9s        # or: k9s

# port-forward every UI (separate terminal, leave running)
make dashboards  # web:5173  lineage:8000  Perses:8080  Greptime:4000  Dapr:8081
k9s cheat-sheet for this demo. : then pods / deploy / svc to switch resources · / filters (type mover, ray, lineage) · l tails logs · d describes · s shells into a pod · Esc backs out. Watch the RESTARTS and READY columns — a demo flow shows up as pods doing work, not restarting.
One caveat you'll want to know. App logs do not appear in k9s pod logs — the services run under OpenTelemetry, so structured logs ship to GreptimeDB over OTLP. k9s l shows only the web-server access lines. For app events (train_denied, dapr_dead_letter_parked, cascade steps) query Greptime at localhost:4000/dashboard — the exact SQL is in each scenario below.

Since the last pull

What got fixed

Eight bugs that CI structurally could not catch — it runs unit + chart-render on fresh clusters, and every one of these only appears when the shipped combination actually runs. The recurring shape: a flag wired in one place but not another, or a check that only tested the easy direction.

1

Web image never booted

bun's workspace layout broke @sveltejs/kit resolution — the Turborepo image CrashLooped. Fixed the runtime-stage topology; boots + renders the search UI.

2

Durable-consumer drift silently killed all delivery ~25 min

a config-changing helm upgrade wedges every JetStream subscription — pods Ready, zero events flow. Added an auto-reconcile step to the stream job.

3

The trainer's authz gate was dead security

FGA env wired only in the movers loop, not the producer that hosts the trainer — a revoked trainer still trained. Now denied → no job. proven live

4

TOKEN env collided with Lance's S3 auth

a bare TOKEN was read as the AWS session token → RustFS 500 → training 100% broken. Every side-probe passed; found it by diffing the raw HTTP on the wire. → TRAIN_TOKEN.

5

MEDALLION_RAY_ENABLED never reached the producer

same movers-only scoping bug → /train returned 409 "not configured" on every call. The train head could never work through the chart.

6

The ServiceAccount flip CrashLooped every Dapr pod security

daprd auto-registers a built-in k8s secret store that needs the SA token the flip removes. Disabled the unused store — keeps the no-mounted-JWT intent.

7

RustFS was write-dead under the security flip security

its uid (1000) didn't match the image/data owner (10001) → reads worked, every write got permission-denied. The read-only "data survived" check missed it. → uid 10001.

8

Model-input version pins were emitted then dropped

280 lineage READ edges held zero versions — the reproducibility pin ("which feature version made this model") was lost at ingest. Now persisted + a new GET /runs/{id}/inputs API.

+

Trainer lineage credential feature

training provenance was silently 401'd under auth — all of it lost. Now authenticates as service-trainer and lands, FGA-bounded. e2e-guarded.

+

Media stages now run on Ray feature

blob columns forced an in-process fallback. Verified live that lance-ray 0.4.2 strips blob typing, added a pylance round-trip + inline derive. /ingest-media now runs as a Ray job, blob-v2 preserved.

+

PSA sidecar hardening chart

a gated dapr.sidecarRestricted flag stamps the daprd sidecar for PodSecurity restricted — render-verified, parked-on-kind (Vector's hostPath structurally blocks full enforce).

The live demo · run these in order

Six flows, watched in k9s

Each drives one pillar of the platform. Exec the command from inside the lance-ray pod (it carries the Dapr app-token); k9s shows you the work landing.

01

The medallion cascade

one event fans out through four governed stages

raw→bronze→silver→gold
k9s

/ to- — pin the four mover pods (raw-to-bronze, bronze-to-silver, silver-to-gold, media-to-silver). They're the compute that lights up.

run
kubectl exec -it deploy/lance-ns-lance-ray -c lance-ray -- python -c \
 "import os,httpx; print(httpx.post('http://localhost:8000/produce',
 headers={'dapr-api-token':os.environ['APP_API_TOKEN']}).json())"
watch
  • a 202 with a token — the correlation id for this run
  • the four movers tick over in sequence as Dapr delivers each stage trigger
  • the graph grows: gold$catalog ⟵ derived from ⟵ raw_events at localhost:8000

04

Training — Ray Train, not Ray Data

own topic, own identity, own registry

silver$features→ train →models$churn·weights on plain S3
run
kubectl exec -it deploy/lance-ns-lance-ray -c lance-ray -- python -c \
 "import os,httpx; print(httpx.post('http://localhost:8000/train',
 headers={'dapr-api-token':os.environ['APP_API_TOKEN'],'content-type':'application/json'},
 json={'model':'churn','features':[{'dataset':'silver\$features'}]}).json())"
watch
  • 202 with pinned feature versions — reproducibility, recorded
  • a ray-train-* job SUCCEEDED; the run lands in lineage authored by service-trainer (not a human) — the credential that was silently 401'ing is now closed
  • the model registry is a Lance dataset models$churn; the actual weights.json / (real: .safetensors) are plain S3 objects under models/churn/<token>/
05

Resilience — dead-letter, not data loss

a poison message parks, it never vanishes

k9s

filter nats-box; shell in (s) and run nats stream ls — you'll see the DLQ stream beside LINEAGE / MEDALLION / TRAINING.

run

Publish a malformed trigger; the app DROPs it, Dapr exhausts retries and parks it on the per-app dlq.* topic. The subscriber's /dlq-event route logs it loudly.

watch
# the park is an ERROR in Greptime, with the token — not gone, parked
SELECT timestamp, severity_text, body FROM opentelemetry_logs
 WHERE body = 'dapr_dead_letter_parked' ORDER BY timestamp DESC;

On registry vs tracking, since it came up. The model files (config.json, .safetensors) are plain objects in RustFS under models/<model>/<token>/ — Lance never stores the bytes, only a pointer-registry (models$<model>, with time-travel as versioning). That's why MLflow-as-registry was rejected (three theses: no second state-of-record, authz stays in OpenFGA, no metadata the graph can't traverse). Models live in their own namespace:models — a peer of gold, not inside it — so the trainer identity never overlaps a mover's.
